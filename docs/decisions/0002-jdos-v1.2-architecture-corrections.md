# ADR-0002: Adopt JDOS v1.2 Architecture Corrections

- **Status:** Accepted
- **Date:** 2026-06-07
- **Owners:** Product owner and architecture owner
- **Decision scope:** Commands/events, request intake, memory consent, embeddings, backups, Settings, Audit, models, and NATS

## Context

The JDOS v1.0 architecture audit scored the baseline 78/100 and identified
ambiguities in command/event semantics, Gateway-to-Core mutation flow, memory
consent, embedding selection, sensitive NATS payloads, backup exclusions,
Settings/Audit ownership, model verification, and NATS operations.

JARVIS PRD v1.1 approves `nomic-embed-text` as the local embedding model. The
locked JDOS technology stack and local/privacy/offline constraints remain
unchanged.

## Decision

Adopt
`docs/architecture/JDOS_v1.2_Architecture_Corrections_Addendum.md` as the
authoritative correction baseline.

Specifically:

- Separate imperative, single-owner commands from factual, multi-subscriber
  events.
- Route API mutations through Orchestration Command Intake, transactional
  outbox, NATS, and the registered command owner.
- Require explicit active consent for durable memory.
- Use `nomic-embed-text` locally through Ollama for embeddings.
- Prohibit content-bearing durable NATS payloads.
- Encrypt backups locally and exclude every secret-bearing source.
- Establish Settings and Audit as explicit service/data owners.
- Verify all four approved models during Phase 01.
- Enforce named NATS streams, retention, size, retry, dead-letter, ownership,
  permissions, and replay policy.

## Consequences

### Positive

- Removes ambiguous mutation paths and command ownership.
- Reduces sensitive-data persistence and subscriber exposure.
- Makes memory consent and deletion enforceable.
- Makes Phase 01 model and NATS acceptance measurable.

### Negative

- Requires content-reference resolution and more explicit command contracts.
- Adds consent, Settings, Audit, and NATS governance implementation work.
- Requires local backup-key and model-digest operations.

## Validation

Documentation validation must prove stack preservation, required correction
sections, command/event ownership, reference-only payload examples, model
checklist coverage, Mermaid validity, and resolved relative links.

## Rollback or Supersession

This decision may be superseded only by an ADR that preserves local-first,
privacy-first, offline-first, event-driven operation and the locked technology
stack unless the product charter itself is replaced.
