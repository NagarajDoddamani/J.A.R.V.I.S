# Lockfile Policy

**JDOS version:** 1.2 · **Effective date:** 2026-06-07

JARVIS requires reproducible installs. The lockfile policy
enforces the same dependency graph on every developer machine, on
the CI runner, and in production images. The policy is enforced
by the bootstrap script, the CI workflow, and the architecture
fitness test.

## Authoritative Lockfiles

| Tool | File | Owner | Generator command |
|---|---|---|---|
| `uv` | `backend/uv.lock` | `backend/pyproject.toml` | `cd backend && uv lock` |
| `pnpm` | `pnpm-lock.yaml` | root + every workspace `package.json` | `pnpm install --lockfile-only` |

Both lockfiles are listed in `.gitignore` by intent: they are
generated by the toolchain on demand, not committed as source.
Every operator must regenerate the lockfile when changing a
manifest.

## Generation

```bash
# Backend (Python)
cd backend
uv lock

# Frontend / shared / tools (Node)
cd ..
pnpm install --lockfile-only
```

## Verification

The verifier at `tools/lockfile/verify.py` runs:

* `uv lock --check` — fails if `uv.lock` is out of sync with
  `backend/pyproject.toml`.
* `pnpm install --frozen-lockfile` — fails if `pnpm-lock.yaml` is
  out of sync with the workspace `package.json` files.

Run the verifier locally:

```bash
python -m tools.lockfile.verify
python -m tools.lockfile.verify --generate
```

## Bootstrap Integration

The bootstrap scripts (`tools/bootstrap/bootstrap.sh` and
`tools/bootstrap/bootstrap.ps1`) call the verifier and fail the
session if either lockfile is missing or stale.

## CI Integration

`.github/workflows/ci.yml` runs the verifier in the foundation
job before lint and tests:

```yaml
- name: Verify lockfiles
  run: python -m tools.lockfile.verify
```

A red CI blocks merges when a manifest is changed without a
matching lockfile refresh.

## Architecture Fitness Gate

`tests/test_architecture_fitness.py` enforces the policy:

* `uv.lock` is listed in `.gitignore`.
* `pnpm-lock.yaml` is listed in `.gitignore`.
* `tools/lockfile/verify.py` exists and imports the policy.

## Failure Modes

| Symptom | Likely cause | Fix |
|---|---|---|
| `uv lock --check` fails after a dependency bump | `uv.lock` not regenerated | `cd backend && uv lock` |
| `pnpm install --frozen-lockfile` fails | A workspace `package.json` was edited | `pnpm install --lockfile-only` |
| `uv.lock` is committed | Author overrode `.gitignore` | `git rm --cached backend/uv.lock` |
| Different lockfile hash across machines | Toolchain version drift | Pin the same `uv` and `pnpm` versions everywhere |

## Operational Rule

A manifest change without a matching lockfile refresh is a
release-blocker. The CI gate is the authoritative validator.
